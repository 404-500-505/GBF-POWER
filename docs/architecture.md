# 系统架构

## 组件

- Windows 客户端在本机启动受控 HTTP/SOCKS 转发、设备身份和可选素材缓存，不向界面显示节点地址。
- 控制服务负责激活码、最多设备数、设备公钥、线路选择、节点状态和计量数据；运营接口只监听数据目录中的 Unix Socket。
- 主节点转发器与控制服务同进程运行，远程网关以独立 `gateway` 子命令运行。
- 管理端通过单独的 SSH 管理身份访问控制机，再调用 Unix Socket；管理 SSH 与普通设备凭据完全分离。

## 激活与连接流程

1. 客户端在本机生成独立 Ed25519 设备密钥。
2. 激活码只用于首次绑定设备公钥；控制端按激活码的设备上限决定是否接受。
3. 后续状态检查由设备私钥签名，不再把激活码当作长期传输凭据。
4. 激活 API 使用 HTTPS，客户端固定控制服务叶证书的 SHA-256 摘要。
5. 控制端把已授权设备公钥提供给主节点；远程节点使用短期授权租约，过期后必须重新向控制端获取。
6. 客户端根据用户偏好和控制端返回的节点信息建立 SSH 动态转发，只把规则命中的目标送入节点。

## 多节点状态

远程节点用自己的 Ed25519 身份密钥签名状态上报。控制端验证节点 ID、时间戳、随机数和签名，过期或重复上报不计入在线状态。在线设备数来自当前已认证会话，不由历史流量或陈旧上报推断。

线路选择综合节点健康、容量、近期负载和客户端偏好。它不是通用负载均衡器：目标仍由最小白名单限制，节点异常时只在已配置的合法节点间切换。

## 数据边界

- 控制状态：`/var/lib/gbf-power/control`，权限 `0700`，状态文件由服务账户持有。
- 控制配置和私钥：`/etc/gbf-power/control`，私钥权限 `0600`。
- 远程网关配置和两把节点私钥：`/etc/gbf-power/gateway`，只在目标服务器生成。
- Windows 设备密钥：用户配置目录的 `runtime/ssh`，绝不进入安装包。

本项目不携带生产地址、证书、激活数据、管理密钥或运行数据库。具体安全假设见[安全模型](security-model.md)。
