# 安全模型

## 安全边界

真正的边界是设备公钥授权、节点身份签名、TLS 证书摘要固定、短期租约、目标白名单和最小系统权限。隐藏 IP、客户端界面、PAC 文件和安装包混淆都不是安全边界。

拿到安装包但没有有效激活码的用户不能把新设备公钥登记到控制端。复制一台已激活设备的私钥则可能冒充该设备，因此设备密钥被视为凭据：应限制 ACL、支持单设备撤销，并在怀疑泄露时换新码重新绑定。停用旧激活码不会永久封禁硬件，设备仍可用新的有效码重新激活。

网关只接受控制端提供的已授权公钥，并只转发规则允许的域名、主机与端口。篡改 PAC 或客户端配置不能扩大网关白名单；部署者仍应使用云防火墙、主机防火墙和出站 ACL 做第二层限制。

## 密钥职责

- 设备私钥：客户端本地生成，用于设备身份；不能预置在安装包。
- SSH 主机私钥：每个网关本地生成，用于服务器身份；管理电脑只接收公钥。
- 节点身份私钥：每个远程网关本地生成，用于签名控制请求与计量上报；管理电脑只接收公钥。
- TLS 私钥：只在控制节点保存，权限 `0600`；客户端仅内置证书摘要。
- 管理 SSH 私钥：由运营者单独保管，不属于普通客户端或激活系统。

## 已知限制

- 撤销通过租约收敛，既有远程节点缓存授权可能在约 30 秒内继续有效。
- 一码两台是服务端策略，不等于硬件不可克隆；密钥泄露仍需撤销设备。
- 应用层白名单不能防御服务器被 root 入侵，也不能代替供应链审查和系统更新。
- 自签证书可用，但必须安全分发新的证书摘要；摘要变更前旧客户端不会自动信任。
