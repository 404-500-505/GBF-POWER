# 日常运维

## 监控

至少观察控制服务状态、节点最后上报、节点负载、当前设备与连接数、上下行速率、累计流量和公开页探测。客户端 Ping 只说明 ICMP 探测，不代表游戏请求丢包；判断体验要结合最终节点丢包、TCP 重传、HTTPS 首包和实际请求耗时。

在线状态以近期认证会话为准。设备流量归零但 SSH 保持连接时仍可能在线；陈旧远程节点上报不会永久把设备标为在线。

## 激活码与设备

- 激活码默认最多绑定两台设备；创建时记录用途、到期时间和备注。
- 停用激活码应阻止其继续授权，但不永久封禁硬件；用户可输入新码重新绑定。
- 私钥疑似泄露时撤销具体设备，不只停用原码。
- 解绑前核对设备备注、最后在线和流量，避免误踢其他用户。

管理命令只通过控制机本地 Unix Socket执行，例如：

```bash
sudo -u gbf-control /usr/local/lib/gbf-power/gbf-activation \
  --admin /var/lib/gbf-power/control/admin.sock list
```

## 备份与恢复

停止或短暂停写后备份 `/var/lib/gbf-power/control`，保持目录 `0700`、文件 `0600`，加密存储并测试恢复。不要把状态、日志、密钥或备份放进源码仓库。

恢复时先验证所有者和权限，再在隔离环境启动同版本程序。不要用空状态覆盖现网；部署脚本设计为保留 `state.json`，但不能替代备份。

## 更新与证书轮换

先在新节点或维护窗口运行离线配置检查和测试，再执行安装器。控制证书变更会改变客户端与远程网关固定的 SHA-256 摘要；应先发布包含新摘要的客户端/网关配置，安排切换窗口，保留可验证的回滚证书。

## 容量

当晚高峰 P95 接近端口容量或 RTT/重传随并发明显上升时，优先扩充单节点带宽或增加经过用户网络实测的节点。自动选择只是调度，不会修复上游拥塞。对明显不属于授权业务的大流量，先缩小白名单，再使用主机或网络层限速。
